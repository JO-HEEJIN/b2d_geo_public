# 도로명주소 데이터 명세 (juso.go.kr)

출처: 주소기반산업지원서비스(business.juso.go.kr)가 제공하는 공식 활용가이드
PDF에서 직접 추출한 내용이다. 모든 컬럼 레이아웃은 가이드 PDF 원문을 그대로
옮긴 것이며, 좌표계 정보는 사이트 카탈로그 API 응답 원문을 인용했다.

조사 일자: 2026-07-03.

## 1. 파일 포맷 공통 규격

건물DB / 주소DB / 도로명주소 한글DB 등 텍스트 계열 유통자료는 아래 공통 규격을
따른다. 각 가이드 PDF 하단에 다음 문구가 명시되어 있다 (verbatim 인용).

> ※ 컬럼간 구분은 파이프('|') 이용
> ※ 파일 인코딩 : MS949

정리하면 다음과 같다.

- 인코딩: **MS949** (= CP949, EUC-KR 확장 슈퍼셋). UTF-8 아님.
- 구분자: **파이프 `|`**.
- 헤더 행: **없음** (첫 행부터 데이터).
- 확장자: `.txt`.
- NULL 값: 빈 문자열로 표기되는 컬럼이 다수 존재 (각 레이아웃의 비고 참조).
- 제공 단위: 전체분은 **시도별**로 분할 제공. 갱신은 월변동 / 일변동 파일로 제공.

주의: 적재 전 스키마 검증 시 컬럼 수와 타입을 아래 레이아웃과 대조하고,
MS949 → UTF-8 디코딩을 반드시 선행할 것.

  - `rnaddrkor_mod` : 도로명주소 한글
  - `jibun_rnaddrkor_mod` : 도로명주소 관련지번
- 일변동분:
  - `AlterD.JUSUKR.YYYYMMDD.TH_SGCO_RNADR_MST` : 도로명주소 한글
  - `AlterD.JUSUKR.YYYYMMDD.TH_SGCO_RNADR_LNBR` : 도로명주소 관련지번

`지역명` 자리에는 시도 단위 명칭이 들어간다 (전체분은 시도별 분할 제공).

건물DB / 주소DB의 개별 파일명은 가이드 PDF에서 별도로 확인 필요하나, 본 조사
시점에는 변동분 파일명 예시(`관련지번_변동분.txt`, `주소_변동분.txt`,
`지번_변동분.txt`, `부가정보_변동분.txt`, `개선_도로명코드_변경분.txt`)만
확인되었다. 실물 다운로드 후 파일명 확정 필요.

## 4. 다운로드 접근 방법

### 4.1 사이트 구조 변경 (중요)

business.juso.go.kr는 현재 **Vue SPA(단일 페이지 앱)** 로 개편되었다. 과거
문서/코드에서 참조하던 `.do` 경로(`attrbDBDwldList.do`, `geoDBDwldList.do` 등)는
모두 **HTTP 404**를 반환한다. 데이터는 JSON API를 통해 조회된다.

- DB 카탈로그 조회: `POST /api/jst/selectBabsRtlDtaDtlList` (인증 불필요, 31개 DB 목록 + 좌표계 설명 반환)
- 공개 여부 필드: 응답의 `RLS_YN` (`Y`=공개하는 주소, `N`=제공하는 주소)

### 4.2 공개하는 주소 (승인 불필요, 직접 다운로드)

로그인 후 바로 다운로드 가능. `RLS_YN=Y` 항목:

- 도로명주소 한글 / 도로명주소 영문
- 건물DB, 주소DB
- 도로명, 상세주소 표시, 상세주소 동 표시, 상세주소DB
- 사물주소, 사물주소DB
- 사서함주소DB, 영문도로명주소DB, 명예도로

### 4.3 제공하는 주소 (연계신청 + 관할 기관장 승인 필요)

`RLS_YN=N` 항목. 다운로드하려면 연계신청 후 승인 절차 필요. 전자지도 설명
원문: "신청지역을 관할하는 기관장의 승인에 따라 다운로드가 가능". 신청지역이
2개 이상 시군구면 시도지사 승인, 2개 이상 광역시/전국 요청이면 **행정안전부**
승인 절차를 거친다.

해당 항목:

- 도로명주소 출입구 정보, 도로명주소 건물 도형, 건물군 내 상세주소 동 도형
- 사물주소 시설 기준점 / 도형
- 기초번호, 국가지점번호 중심점 / 도형
- 도로명이 부여된 도로 도형, 구역의 도형, 기타자료
- 도로명주소 전자지도
- **위치정보요약DB**, **내비게이션용DB**, **기초번호위치정보DB**
- 민원행정기관 전자지도, 명예도로 도형, 내부도로 전자지도

사용자가 브라우저에서 해야 할 절차 (제공하는 주소 신청):

1. business.juso.go.kr 회원가입/로그인 (이름/생년월일(사업자번호)/전화/이메일 필요).
2. 제공하는 주소 → 해당 DB → 신청(장바구니 담기 후 신청서 작성).
3. 관할 기관장 승인 대기 → 승인 후 다운로드. 전국/광역 요청은 행안부 승인.

### 4.4 활용가이드 PDF 직접 다운로드 URL 패턴

공개 DB의 활용가이드 PDF는 인증 없이 직접 다운로드 가능하다. 패턴:

```
GET https://business.juso.go.kr/api/jst/download??reqType=<REQTYPE>&fileName=<KOR>.pdf&realFileName=<REALFILE>&regYmd=2023
```

주의사항:
- URL에 물음표가 **두 개(`??`)** 붙는다 (사이트 원본 코드 그대로).
- `fileName`(한글 표시명)은 URL 인코딩 필요. `realFileName`이 실제 파일 식별자.
- `regYmd=2023` 파라미터 필수.

확인된 공개 가이드 reqType / realFileName:

| DB | reqType | realFileName |
|----|---------|--------------|
| 건물DB | `rdnm` | `rdnmDBGuide.pdf` |
| 주소DB | `mtchg` | `mtchgDBGuide.pdf` |

| 도로명주소 영문 | `rnadr_eng` | `rnadr_engDBGuide.pdf` |
| 영문도로명주소DB | `engj` | `engjDBGuide.pdf` |
| 상세주소DB | `detailadr` | `detailadrDBGuide.pdf` |
| 상세주소 표시 | `detailadr_ex` | `detailadr_exDBGuide.pdf` |
| 상세주소 동 표시 | `adrdong` | `adrdongDBGuide.pdf` |

## 5. 좌표계

좌표계 정보는 카탈로그 API(`selectBabsRtlDtaDtlList`) 응답의 각 DB 설명문에
포함되어 있다. 아래는 원문 인용이다.

- **위치정보요약DB**: `"좌표계(ITRF2000), 기준타원체(GRS80)"`
- **내비게이션용DB**: `"좌표계(ITRF2000), 기준타원체(GRS80)"` (좌표: 건물중심점, 주출입구, 보조출입구)
- **도로명주소 전자지도**: `"좌표계(ITRF2000), 기준타원체(GRS80), 투영법(UTM), 장반경(6,378,137m)"`
- **민원행정기관 전자지도**: `"좌표계(ITRF2000), 기준타원체(GRS80), 투영법(UTM), 장반경(6,378,137m)"`
- **기초번호 / 기초번호위치정보DB**: `"경위도좌표, 기준타원체(WGS84)"`

### EPSG 미명시 — 하드코딩 금지

가이드/설명 어디에도 EPSG 코드가 **문자 그대로 명시되어 있지 않다**.
ITRF2000 / GRS80 / UTM 투영은 UTM-K 계열로, 통상 **EPSG:5179 (Korea 2000 /
Unified CS)** 로 매핑되지만 다음 이유로 확정 금지:

- 문서상 데이텀 표기가 "ITRF2000"이며 EPSG:5179의 명칭 "Korea 2000"과 라벨이
  다르다 (두 실현치는 cm 수준 근사이나 동일 문자열은 아님).
- 투영 파라미터(중앙자오선, 축척계수, false easting/northing)가 문서에 명기되지
  않았다.

따라서 프로젝트 규칙대로 좌표계는 명세서로 확정 전 코드에 박지 않는다.
위치정보요약DB / 내비게이션용DB 실물 레이아웃 가이드(신청 후 확보)에서
투영 파라미터를 확인해 EPSG를 확정할 것. 참고 UTM-K 파라미터(확정 필요):
중앙자오선 127.5, 축척계수 0.9996, false easting 1,000,000, false northing
2,000,000. WGS84 경위도 계열(기초번호위치정보DB)은 EPSG:4326으로 추정되나
동일하게 확정 후 사용. 좌표 변환은 PostGIS `ST_Transform`만 사용.

## 6. 미해결 (신청 후 확보 필요)

- **위치정보요약DB** 컬럼 레이아웃 (X/Y 좌표가 어느 컬럼인지 포함).
- **내비게이션용DB** 컬럼 레이아웃 (건물중심점 / 주출입구 / 보조출입구 좌표
  컬럼 위치).
- 위 두 DB의 정확한 EPSG (투영 파라미터 확인용 레이아웃 가이드).

받아야 실물과 레이아웃 문서를 확보할 수 있다.
